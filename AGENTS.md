# AGENTS.md

Operating guide for agents and humans editing this repository.

This is a **personal, multi-user NixOS flake**, not an application codebase. There is no test
suite. "Correct" means: the flake evaluates, the configuration builds, and the user's desktop
still behaves as documented below.

---

## 1. Ground rules

1. **Read before editing.** Open the relevant module and its import chain first.
2. **Make the smallest change that solves the request.** Do not refactor, reformat, rename, or
   "clean up" unrelated files.
3. **Never commit, push, rebuild, or update the lockfile unless explicitly asked.**
   A real rebuild changes the running system.
4. **Never edit `flake.lock` by hand.** Use `nix flake update` (or `nix flake update <input>`).
5. **Never edit `hardware-configuration.nix` by hand.** It is generated by
   `nixos-generate-config`; regenerate it instead of patching values.
6. **Never commit secrets.** API keys belong in `/etc/hermes/hermes.env`, secure-boot keys in
   `/etc/secureboot`, and neither belongs in this repo.
7. **Preserve intentional oddities.** Several packages and comments are deliberate jokes or
   workarounds (for example `supertux`, and the `/usr/bin/prlimit` tmpfile rule). Do not remove
   them because they look unnecessary.
8. **Do not add comments unless they explain a non-obvious workaround.** Existing comments are
   informal; leave their tone alone.
9. **No formatter is configured.** Do not mass-format the repo or introduce a formatter without
   asking. Match surrounding style (2-space indent, loose alignment).
10. **Ask before changing security-sensitive settings:** SSH auth, firewall, secure boot,
    substituters/trusted keys, `fallback`, and user passwords.

## 4. How the flake is wired

`flake.nix` inputs:

- `nixpkgs` — `nixos-unstable`
- `home-manager` — follows `nixpkgs`
- `lanzaboote` — follows `nixpkgs`
- `niri` (sodiboo/niri-flake) — follows `nixpkgs`
- `noctalia` (noctalia-shell) — follows `nixpkgs`
- `nix-hermes` (0xrsydn/nix-hermes-agent) — top-level, not followed
- `spicetify-nix` — not followed
- `claude-desktop` (k3d3) — not followed

Module order for `nixos-main`:

1. `./configuration.nix`
2. `inputs.niri.nixosModules.niri`
3. `inputs.lanzaboote.nixosModules.lanzaboote`
4. `home-manager.nixosModules.home-manager`
5. `nix-hermes.nixosModules.hermes-agent`
6. Inline Home Manager block

Home Manager is configured with:

```nix
home-manager = {
  useGlobalPkgs = true;
  useUserPackages = true;
  extraSpecialArgs = { inherit inputs; };
};
```

All system modules receive `inputs` through `specialArgs = { inherit inputs; }`. Home Manager
modules receive it through `extraSpecialArgs`. Use `inputs.<name>` directly; do not `import`
flake inputs from paths.

Home Manager users and their files:

| User | Home file | Extra imports |
| --- | --- | --- |
| `e` | `home/users/e.nix` | `spicetify-nix.homeManagerModules.default`, plus `noctalia.nix`, `niri.nix` |
| `jsdev` | `home/users/js.nix` | shared config only |
| `php` | `home/users/php.nix` | shared config only |
| `pydev` | `home/users/py.nix` | shared config only |

`home/default.nix` is shared by **all** users. It intentionally does **not** import
`niri.nix` or `noctalia.nix`; those are `e`-specific.

When adding a Home Manager user, update all three places: `modules/users.nix`,
`home/users/<name>.nix`, and the `users.<name>` block in `flake.nix`. Keep `home.username`
and `home.homeDirectory` consistent with the system user.

## 5. Users and host model

| User | Groups | Notes |
| --- | --- | --- |
| `e` | `wheel`, `networkmanager`, `docker`, `audio`, `video`, `devs` | admin; bash; SSH key configured |
| `jsdev` | `networkmanager`, `docker`, `devs` | bash; no `initialPassword` |
| `php` | `networkmanager`, `docker`, `devs` | bash; no `initialPassword` |
| `pydev` | `networkmanager`, `docker`, `devs` | bash; no `initialPassword` |

`devs` is created in `configuration.nix` and all four users are members.

Project sharing is implemented with bind mounts:

| Visible path | Backing path |
| --- | --- |
| `/home/e/projects/js` | `/home/jsdev/projects` |
| `/home/e/projects/php` | `/home/php/projects` |
| `/home/e/projects/py` | `/home/pydev/projects` |

`systemd.tmpfiles.rules` creates `/home/e/projects` with `e:users` and the backing dirs
with `<user>:devs` mode `2775`. Each mount uses
`x-systemd.requires-mounts-for=<backing home>`. Do not replace these with symlinks; the
bind mounts are deliberate.

`systemd.services.project-acls` runs once as root, gated by
`/var/lib/project-acls.done`. It normalizes each backing tree to `<user>:devs`, sets the
setgid bit on directories, and applies `g:devs:rwX` plus default `d:g:devs:rwx` ACLs.
New files inherit group write. To re-run after ownership drift, remove the marker and
start the service (see section 11).

### System behavior worth knowing

- `networking.useDHCP = false`; NetworkManager manages networking.
- `systemd.targets.hibernate.enable = false`; suspend is left enabled.
- `hardware.graphics.enable32Bit = true` for Steam/games.
- `nixpkgs.config.allowUnfree = true`.
- `WLR_NO_HARDWARE_CURSORS=1` and `NIXOS_OZONE_WL=1` are set session-wide.
- Docker is enabled but **does not start on boot** (`enableOnBoot = false`).

### Power

`modules/battery.nix` disables `power-profiles-daemon` on purpose because TLP is used.
The ASUS charge threshold is a oneshot systemd service that writes `80` to
`/sys/class/power_supply/BAT0/charge_control_end_threshold`. TLP uses `quiet`/`power`
on battery and `performance` on AC. Do not enable PPD alongside TLP.

### Secure boot

`modules/boot.nix` uses `lib.mkForce false` on systemd-boot and enables Lanzaboote with
`pkiBundle = "/etc/secureboot"`. Keep `boot.loader.efi.canTouchEfiVariables = true`.
Do not re-enable systemd-boot or remove the `mkForce` without an explicit request.

### Nix settings

`modules/nix-settings.nix`:

- flakes + `nix-command`, `auto-optimise-store`
- `cores = 6`, `max-jobs = 6`
- weekly GC, deleting generations older than 14 days
- substituters: `cache.nixos.org`, `nix-community`, `noctalia`
- **`fallback = false`** — packages not in a configured cache fail instead of building
- `min-free = 4 GiB`
- tmpfiles create `/usr/bin` and symlink `prlimit` from `util-linux` (needed by at least one
  proprietary app; do not delete).

### Networking

`modules/ssh.nix` enables OpenSSH with root login disabled, `AllowUsers = [ "e" ]`,
`e`'s public key, password auth still enabled, Tailscale, nftables, and a firewall
allowing TCP 22 plus the Tailscale interface/port. Final hardening to keys-only,
Tailscale-only, and no public port 22 is staged until Tailscale is running and key login
is verified. Do not silently harden or weaken SSH.

### Hermes agent

`modules/hermes.nix` enables `services.hermes-agent` with a local Ollama custom provider
(`http://localhost:11434/v1`), local terminal backend, and `toolsets = [ "all" ]`.
Secrets come from `/etc/hermes/hermes.env` via `environmentFiles`. Never inline API keys.
The package is also added in `modules/packages.nix` from `inputs.nix-hermes`.

`modules/ollama.nix` enables `services.ollama` with `pkgs.ollama-cpu`. It does **not**
pull models automatically; pull one manually before Hermes can answer:

```bash
sudo -u ollama ollama pull llama3.1
```

GPU acceleration is not enabled; do not switch the package without checking the AMD setup.

## 6. Desktop stack

`modules/desktop.nix` enables **both** Hyprland and Niri, plus Plasma 6, Ly as the display
manager, Flatpak, GVFS, and the GTK/Hyprland/KDE portals. Portal defaults:

- common → `gtk`
- hyprland → `hyprland`, `gtk`
- niri → `gtk`

`home/default.nix` imports `hyprland.nix`, `waybar.nix`, `terminals.nix`, `editors.nix`,
`rofi.nix`, `hyprlock.nix`, `hypridle.nix`, and `fastfetch.nix`.

For user `e`:

- `noctalia.nix` enables Noctalia and disables its systemd service.
- `niri.nix` configures Niri and starts `xwayland-satellite` and `noctalia` at startup.
- `hyprland.nix` starts Waybar, dunst, swww, nm-applet, and blueman-applet.

So Waybar is a Hyprland autostart; under Niri, Noctalia provides the shell. Do not assume
Waybar is running in a Niri session.

`hypridle` is a user service limited to Hyprland via
`ConditionEnvironment=XDG_CURRENT_DESKTOP=Hyprland`; it is not an `exec-once`. Under Niri,
Noctalia handles idle, lock, and DPMS. Do not run both lock stacks.

Keybindings are duplicated between Hyprland and Niri. If you change a binding, update both
files to keep them consistent, unless the request is desktop-specific.

The Waybar config is written with `xdg.configFile` (inline JSONC and CSS), not via
`programs.waybar.settings`. `programs.waybar.enable = true` is still set. Keep that pattern.

### Theme conventions

- Tokyo Night palette (blues/purples, `#89b4fa`, `#cba6f7`, `#cdd6f4`).
- JetBrains Mono / JetBrains Mono Nerd Font.
- Rounded corners, gaps, blur and shadows in Hyprland.
- Wallpapers are set by `swww` in `hyprland.nix` (GIF with `nixoswhite.png` fallback),
  `NixOs.png` in `hyprlock.nix`, and the fastfetch logo.

Image paths are **absolute** (`/etc/nixos/images/...`). This repo is not relocatable as-is;
cloning it elsewhere breaks wallpapers and the fastfetch logo. `NixOs.png` and
`nixoswhite.png` are tracked; `wallpaper.gif` is local-only and ignored.

## 7. Where changes belong

| Change | Location |
| --- | --- |
| New system package | `modules/packages.nix` |
| New system service | new `modules/<topic>.nix`, then import it in `configuration.nix` |
| Shared user package | `home/default.nix` |
| Shared app/desktop config | `home/modules/<app>.nix` + import in `home/default.nix` |
| User-specific package/config | `home/users/<user>.nix` |
| New flake input | `flake.nix`, plus `nix flake update <input>` |
| New user | `modules/users.nix`, `home/users/<name>.nix`, `flake.nix` HM block |
| Host/network/boot/kernel | `configuration.nix` or the relevant `modules/` file |
| Hardware/disk/firmware | `hardware-configuration.nix` via regeneration, not manual edits |

Prefer a topic module over adding more lines to `configuration.nix`. The entry point is kept
small on purpose and should mostly stay a list of imports plus host identity.

## 8. Commands and validation

Run from `/etc/nixos`.

```bash
# Evaluate the flake (fastest sanity check)
nix eval --raw .#nixosConfigurations.nixos-main.config.system.build.toplevel.drvPath

# Check flake outputs without building
nix flake check --no-build

# Build without activating (preferred for agent verification)
sudo nixos-rebuild dry-build --flake /etc/nixos#nixos-main

# Activate (only when the user asks)
sudo nixos-rebuild switch --flake /etc/nixos#nixos-main

# Build for next boot (only when the user asks)
sudo nixos-rebuild boot --flake /etc/nixos#nixos-main

# Update all inputs (only when asked)
sudo nix flake update /etc/nixos

# Update one input
sudo nix flake update <input-name> --flake /etc/nixos

# Roll back
sudo nixos-rebuild switch --rollback

# Garbage collection (deletes generations older than 14 days)
sudo nix-collect-garbage --delete-older-than 14d
```

Interactive shell aliases defined in `configuration.nix`:

- `rebuild` → `sudo nixos-rebuild switch --flake /etc/nixos#nixos-main`
- `rebuild-boot` → `sudo nixos-rebuild boot --flake /etc/nixos#nixos-main`
- `update` → `sudo nix flake update /etc/nixos && rebuild`
- `cleanup` → `sudo nix-collect-garbage --delete-older-than 14d`

Validation expectations:

1. `git diff --check` for whitespace errors.
2. Flake evaluation succeeds.
3. `dry-build` succeeds when feasible.
4. Report exactly what you ran and what you could not run.
5. Do not run `switch`, `boot`, `flake update`, or GC on the user's behalf unless asked.

Because `fallback = false`, a new uncached package may fail during `dry-build`/`switch`.
Do not flip `fallback` to work around it; report the package and let the user decide.

## 9. Nix style conventions in this repo

- Modules use the existing argument style, commonly
  `{ config, pkgs, inputs, ... }:` even when a binding is unused. Keep it consistent.
- `with pkgs; [ ... ]` is standard inside package lists.
- Two-space indentation. Alignment is inconsistent; do not reformat unrelated lines.
- Lists of adjacent strings (for example `systemd.tmpfiles.rules`) are valid without
  separators. Do not "fix" them.
- Inline `xdg.configFile."...".text` is used for JSONC/CSS/Lua configs. Extend the inline
  string rather than introducing a new config-file dependency.
- Use `lib.mkForce`/`lib.mkDefault` only when option merging requires it. `boot.nix` uses
  `mkForce` deliberately.
- Avoid `import` of flake inputs; use `inputs.<name>`.
- Keep `system.stateVersion` and `home.stateVersion` at `24.05` unless performing an
  intentional release migration.
- `inputs.spicetify-nix.legacyPackages.${pkgs.system}` is the expected spicetify namespace.
- Niri bindings are an attrset using `action.*`; Hyprland bindings are strings in `bind`,
  `bindel`, `bindl`, `bindm`.

## 10. Known quirks and landmines

1. **Absolute image paths.** `hyprland.nix`, `hyprlock.nix`, and `fastfetch.nix` hardcode
   `/etc/nixos/images/...`.
2. **Hardware config is generated.** `hardware-configuration.nix` is tracked and no longer
   gitignored. Do not delete it from git or rewrite it manually.
3. **Binary/VM assets are ignored.** `windows/` contains VM images and is gitignored. Do not
   delete it; it is not reproducible from the flake.
4. **`images/` is mostly ignored.** `NixOs.png` and `nixoswhite.png` are tracked;
   `wallpaper.gif` is local-only. Hyprland falls back to `nixoswhite.png` if the GIF is
   missing. Do not assume a clean clone has the GIF.
5. **`fallback = false`.** New packages may fail instead of building. This is intentional.
6. **`supertux` is intentional.** Its comment is a joke. Do not remove it or "correct" the
   comment.
7. **Two desktops.** Hyprland and Niri are both enabled. Changes to shared Home Manager
   modules affect both; desktop-specific changes belong in the matching file. Do not start
   `hypridle` under Niri; Noctalia owns idle/lock/DPMS there.
8. **Two shells/bars.** Waybar is Hyprland-specific; Noctalia is used by Niri for user `e`.
9. **No formatter / no tests.** Validation is evaluation + dry-build. Do not claim tests pass.
10. **Shared project ACLs.** `project-acls` is a one-shot service gated by
    `/var/lib/project-acls.done`. If ownership or default ACLs drift, remove the marker and
    start the service. Do not replace bind mounts with symlinks.
11. **Ollama is CPU-only and manual.** No model is auto-pulled. Run
    `sudo -u ollama ollama pull llama3.1` before expecting Hermes to answer.
12. **SSH hardening is staged.** `e`'s key and `AllowUsers = [ "e" ]` are configured, but
    password auth and public port 22 remain. Do not flip to keys-only/Tailscale-only until
    Tailscale is running and key login is verified.
13. **`/usr/bin/prlimit` shim** is required by some app. Keep the tmpfiles rule.
14. **Secure boot keys** live outside the repo at `/etc/secureboot`. Never copy them in.
15. **`cuda-maintainers` cache was removed.** It returned HTTP 401. Do not re-add it
    without checking the cache status.

## 11. Common recipes

### Add a system package

Add it to `environment.systemPackages` in `modules/packages.nix`. Keep the existing grouping
and comments. If the package is unfree, `allowUnfree` is already true. If it is unlikely to
be cached, warn about `fallback = false`.

### Add a system service

Create `modules/<topic>.nix` with the standard module header, enable the service, and add
`./modules/<topic>.nix` to the `imports` list in `configuration.nix`. Do not append large
service blocks directly to `configuration.nix`.

### Add a shared Home Manager module

1. Create `home/modules/<name>.nix`.
2. Import it in `home/default.nix` if every user should get it.
3. Import it only in `home/users/<user>.nix` if it is user-specific.

If the module needs `inputs`, include it in the function arguments; `extraSpecialArgs`
already provides it.

### Add a per-user package

Add it to `home.packages` in `home/users/<user>.nix`. Use `home/default.nix` instead if all
users need it.

### Add a flake input

1. Add the input in `flake.nix`.
2. If it wraps nixpkgs, set `inputs.nixpkgs.follows = "nixpkgs"`.
3. Add the input to the `outputs` argument list so `inputs.<name>` works.
4. Run `sudo nix flake update <name> --flake /etc/nixos` (only if asked).
5. Wire the module/package where needed.

### Add a user

1. Add the system user and groups in `modules/users.nix`.
2. Create `home/users/<name>.nix` with `home.username`, `home.homeDirectory`,
   `home.stateVersion = "24.05"`, and `imports = [ ../default.nix ];`.
3. Add the `users.<name>` block in `flake.nix` under `home-manager`.
4. If project bind mounts are needed, add tmpfiles entries, `fileSystems` mounts, and the
   user's backing directory to the `project-acls` script in `configuration.nix`.

### Pull an Ollama model

The service is CPU-only and does not auto-pull. Pull a model before using Hermes:

```bash
sudo -u ollama ollama pull llama3.1
```

### Re-run project ACL normalization

```bash
sudo rm /var/lib/project-acls.done
sudo systemctl restart project-acls
```

### Change wallpapers

- Hyprland: `exec-once` swww line in `home/modules/hyprland.nix` (GIF with
  `nixoswhite.png` fallback).
- Lock screen: `background` in `home/modules/hyprlock.nix` (tracked `NixOs.png`).
- Fastfetch: `logo.source` in `home/modules/fastfetch.nix`.
- `images/NixOs.png` and `images/nixoswhite.png` are tracked; `images/wallpaper.gif` is
  ignored. Update the `.gitignore` negations when adding another tracked image, and keep
  paths absolute.

### Update and roll back

```bash
sudo nix flake update /etc/nixos
sudo nixos-rebuild switch --flake /etc/nixos#nixos-main
# if something breaks:
sudo nixos-rebuild switch --rollback
```

Old generations are also available in the boot menu.

## 12. Agent workflow checklist

Before editing:

- [ ] Locate the correct module using the decision table in section 7.
- [ ] Read the file and its import chain.
- [ ] Check whether the change affects Hyprland, Niri, or both.
- [ ] Check whether the change touches secrets, boot, SSH, or the lockfile.

While editing:

- [ ] Keep the diff minimal and scoped.
- [ ] Preserve existing comments and intentional packages.
- [ ] Do not hand-edit generated or locked files.
- [ ] Keep state versions unchanged.

After editing:

- [ ] `git diff --check`
- [ ] `nix eval --raw .#nixosConfigurations.nixos-main.config.system.build.toplevel.drvPath`
- [ ] `nix flake check --no-build` or `sudo nixos-rebuild dry-build --flake /etc/nixos#nixos-main`
- [ ] Summarize changed files and validation results.
- [ ] State clearly if a real rebuild, lock update, or commit was not performed.

Final rule: when in doubt, do less. This configuration controls a real machine's boot,
security, and desktop session.
